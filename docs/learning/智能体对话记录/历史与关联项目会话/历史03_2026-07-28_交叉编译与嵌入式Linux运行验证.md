### 解决方案

针对基于 CMake + Qt (Core, Gui, Widgets) 的 RTSA 项目，从 Windows 编译出 Linux 可运行的二进制可执行文件，有以下两种主流方案及 Linux 端部署运行方法：

---

### 方案一：Windows 下通过 CMake 交叉编译（以 `x86_64-linux-gnu` 或 ARM Linux 为例）

需要在 Windows 下安装支持 Linux 目标架构的 GCC 工具链（如 `x86_64-linux-gnu-g++` 或 `aarch64-linux-gnu-g++`）及对应目标系统的 Linux Qt 库头文件与 `.so` 库（Sysroot）。

#### 1. 创建交叉编译配置文件 `toolchain-linux.cmake`

在项目根目录下新建 `toolchain-linux.cmake`：

```cmake
set(CMAKE_SYSTEM_NAME Linux)
set(CMAKE_SYSTEM_PROCESSOR x86_64) # 如果是 ARM 架构改写为 aarch64

# 指定交叉编译器路径（请根据本地安装路径修改）
set(TOOLCHAIN_PREFIX x86_64-linux-gnu)
set(CMAKE_C_COMPILER   ${TOOLCHAIN_PREFIX}-gcc)
set(CMAKE_CXX_COMPILER ${TOOLCHAIN_PREFIX}-g++)

# 指定目标系统的 Sysroot 根目录（必须包含 Linux 下安装好的 Qt5/Qt6 库及头文件）
set(CMAKE_SYSROOT "C:/sysroot/x86_64-linux")

# 寻找头文件和库文件的优先路径设置
set(CMAKE_FIND_ROOT_PATH ${CMAKE_SYSROOT})
set(CMAKE_FIND_ROOT_PATH_MODE_PROGRAM NEVER)
set(CMAKE_FIND_ROOT_PATH_MODE_LIBRARY ONLY)
set(CMAKE_FIND_ROOT_PATH_MODE_INCLUDE ONLY)
set(CMAKE_FIND_ROOT_PATH_MODE_PACKAGE ONLY)

# 显式指定 Linux Qt CMake 配置文件所在目录
set(Qt5_DIR "${CMAKE_SYSROOT}/usr/lib/x86_64-linux-gnu/cmake/Qt5")
set(Qt6_DIR "${CMAKE_SYSROOT}/usr/lib/x86_64-linux-gnu/cmake/Qt6")
```

#### 2. 执行 CMake 编译命令

在 Windows PowerShell 中执行：

```powershell
# 1. 创建并进入 build 目录
mkdir build-linux
cd build-linux

# 2. 生成 Makefile / Ninja 构建文件
cmake -G "Ninja" -DCMAKE_TOOLCHAIN_FILE=../toolchain-linux.cmake -DCMAKE_BUILD_TYPE=Release ..

# 3. 编译出 Linux 可执行文件
cmake --build . --config Release
```

### 方案二：Docker 一键编译（推荐：免配置 Windows 复杂的交叉编译环境）

由于 Qt 依赖 `moc` 工具和 C++ ABI 绑定，直接使用包含 Qt 环境的 Linux Docker 镜像构建最为高效。

#### 1. 在项目根目录创建 `Dockerfile.build`

```dockerfile
FROM ubuntu:22.04

ENV DEBIAN_FRONTEND=noninteractive

# 安装 C++ 编译器、CMake 及 Qt 依赖
RUN apt-get update && apt-get install -y \
    build-essential \
    cmake \
    qtbase5-dev \
    qtchooser \
    qt5-qmake \
    qtbase5-dev-tools \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /app
```

#### 2. 一键构建出 Linux 目标二进制文件

在 Windows 上通过 PowerShell 执行：

```powershell
# 构建镜像并执行编译，输出产物映射回本地 build-docker 目录
docker build -t rtsa-builder -f Dockerfile.build .
docker run --rm -v "${PWD}:/app" rtsa-builder bash -c "mkdir -p build-docker && cd build-docker && cmake -DCMAKE_BUILD_TYPE=Release .. && make -j$(nproc)"
```

执行完成后，`build-docker/src/rtsa_app` 即为 Linux 原生可执行二进制文件。

### Linux 端部署与运行

编译出的 `rtsa_app` 放到 Linux 系统上时，因依赖 Qt 动态库（`.so`），直接运行可能会提示 `cannot open shared object file`。

#### 1. 打包 Qt 依赖库

推荐在 Linux 编译机或目标机上使用 [linuxdeployqt](https://github.com/probonopd/linuxdeployqt) 进行依赖一键打包：

```bash
# 下载 linuxdeployqt 工具
wget https://github.com/probonopd/linuxdeployqt/releases/download/continuous/linuxdeployqt-continuous-x86_64.AppImage
chmod +x linuxdeployqt-continuous-x86_64.AppImage

# 自动收集 Qt 依赖库并放置在 rtsa_app 同级目录
./linuxdeployqt-continuous-x86_64.AppImage ./rtsa_app -appimage -unsupported-allow-new-glibc
```

#### 2. 在目标 Linux 机器上运行

将打包好的产物文件夹打包上传到目标 Linux，创建启动脚本 `run.sh`：

```bash
#!/bin/bash
# 解决动态链接库路径问题
DIR="$( cd "$( dirname "${BASH_SOURCE[0]}" )" >/dev/null 2>&1 && pwd )"
export LD_LIBRARY_PATH=$DIR/lib:$LD_LIBRARY_PATH
export QT_PLUGIN_PATH=$DIR/plugins

# 启动程序
$DIR/rtsa_app "$@"
```

赋予权限并运行：

```bash
chmod +x run.sh rtsa_app
./run.sh
```

### 问题背景与逻辑说明

你当前的项目 `RTSA_Analyzer` 采用 **C++17 + CMake + Qt (Core, Gui, Widgets)** 构建。

1. **交叉编译难点**：跨操作系统（Windows -> Linux）交叉编译纯 C++ 库较为简单，但由于 Qt 框架依赖 `moc`（Meta-Object Compiler）预编译器以及 Qt 对应的 GUI 动态链接库（`libQt5Widgets.so` 等），因此必须确保交叉编译器调用的 Qt 库是 Linux 版本且 ABI 兼容。
2. **方案对比**：
   - **Toolchain 方式**适合目标机是嵌入式 Linux（如 RK3588, Imx8, Jetson）的场景，需要从交叉编译链厂商处获取带有 Qt 环境的 `sysroot`。
   - **Docker / WSL2 方式**适合目标机是普通 Linux x86_64（如 Ubuntu/CentOS 服务器或 PC）的场景，省去了在 Windows 下艰难配置 Linux 交叉工具链的过程。

### 解决方案

最方便、最不踩坑的方式是：**利用「虚拟机 Linux」作为交叉编译中枢，通过 VS Code / Qt Creator 远程连接虚拟机编译，再将编译产物部署到开发板**。

**原因**：在 Windows 上直接交叉编译到 ARM Linux 极其复杂（路径、大小写敏感、ABI 冲突），而在 Linux 虚拟机中只需安装目标板卡（ARM64/ARM32）的交叉工具链与依赖库，配置极度简单且高度稳定。

---

### 第一步：在 Linux 虚拟机中安装交叉构建环境

在 Linux 虚拟机终端中执行以下命令（以常见的 64 位 ARM 架构 `aarch64` 为例；若开发板是 32 位 ARM，将 `aarch64` 替换为 `arm-linux-gnueabihf`）：

```bash

sudo apt install -y build-essential cmake ninja-build gcc-aarch64-linux-gnu g++-aarch64-linux-gnu

mkdir -p ~/sysroot
# 使用 rsync 自动从开发板拉取库文件（将 <board_ip> 替换为开发板实际 IP）
rsync -avz --safe-links root@<board_ip>:/lib ~/sysroot/
rsync -avz --safe-links root@<board_ip>:/usr/lib ~/sysroot/usr/
rsync -avz --safe-links root@<board_ip>:/usr/include ~/sysroot/usr/
```

> **注意**：如果板卡厂商（如飞凌、正点原子、迅为等）提供了交叉编译 SDK（例如 `environment-setup-aarch64-xxxx-linux` 脚本），在虚拟机中运行 `source environment-setup-...` 即可一步搞定环境，无需自己配置 `sysroot`。
