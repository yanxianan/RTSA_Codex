# 纯 CPU 渲染帧率问题与优化方案

## 问题分析

在无 GPU 的 ZU47DR 开发板上，频谱曲线、坐标轴、标记以及瀑布图等界面内容均需要由 CPU 通过 Qt Raster 光栅化完成，因此显示帧率会受到 CPU 计算能力、内存带宽和显示后端提交能力的共同限制。当频谱点数达到数千至数万个、显示分辨率提升至 2K，并同时保持较高输入帧率时，每一显示帧都可能包含频率坐标映射、包络计算、折线端点生成、像素光栅化、文字绘制、图像合成和 Framebuffer 提交等大量工作；如果这些操作全部在 GUI 线程中同步执行，主线程将被长时间占用，窗口事件处理、参数交互和界面重绘会相互阻塞。与此同时，板端 CPU 还需要承担 DMA 数据接收、协议解析、频谱处理和其他系统任务，显示线程与采集处理线程争用计算资源和内存带宽后，更容易出现绘制耗时增加、有效显示帧率下降和画面更新迟滞。若输入帧率高于界面实际刷新能力，而系统又为每个输入帧保留绘制任务，积压任务会不断增加，导致频谱画面落后于实际采集数据；静态网格和坐标文本的重复绘制、整幅图像反复复制以及频繁内存分配也会进一步放大纯 CPU 渲染路径的开销。

## 解决方案

针对纯 CPU 渲染帧率受限的问题，当前实现采用面向多核 CPU 的任务级并发调度与多层次绘制优化相结合的方法。在总体结构上，数据源使用独立采集线程完成频谱数据生成、DMA 接收和管线处理，频谱控件使用专用后台线程执行离屏 Raster 渲染，GUI 主线程只负责读取已完成图像并提交到窗口，使采集处理、图像光栅化和界面响应能够由操作系统调度到不同 CPU 核心并发执行，避免较重的绘制工作阻塞主线程。频谱绘制前首先按照绘图区像素宽度执行逐列最小值和最大值包络压缩，将最终绘制点数由原始频点规模降低到屏幕宽度量级，在减少折线和像素计算量的同时保留窄带峰值；背景、边框、网格、坐标轴和刻度文字被缓存为 RGB16 静态层，仅在窗口尺寸、频率范围、幅度范围或主题变化时重新生成，每帧只绘制动态频谱曲线、Marker 和必要文本。后台渲染线程将完整图像绘制到离屏 RGB16 缓冲区，通过前后图像切换和 Qt 图像隐式共享减少锁持有和整图复制，并通过“最新任务覆盖旧任务”的机制避免渲染请求排队；GUI 线程收到更新通知后，仅使用 `paintEvent()` 提供的脏矩形贴入发生变化的部分，从而减少 2K 全屏范围内的无效内存搬运。显示调度采用固定周期定时器读取 `LatestFrameStore` 中最新完整帧，当输入速率高于显示能力时主动丢弃过期显示帧而不累积延迟；瀑布图使用 `Indexed8` 环形缓冲区保存历史数据，只更新新增行和当前可见区域，降低大尺寸图像的内存占用与重复绘制成本。此外，渲染过程中的几何数组、图像对象和缓冲区尽量预分配并重复使用，并关闭不必要的抗锯齿，以降低逐帧内存分配和像素级计算开销；离屏图像尚未就绪时则保留同步 Raster 绘制作为冷启动和异常状态下的兜底路径。通过上述多核并发、包络降采样、静态缓存、脏区贴图、最新帧覆盖、环形缓冲和缓冲区复用等措施，系统在无 GPU 条件下降低了频谱与瀑布图的单帧绘制成本，提高了 CPU 资源的并行利用率和显示刷新稳定性，并为达到不低于 30 FPS 的实时显示目标提供了实现基础。
