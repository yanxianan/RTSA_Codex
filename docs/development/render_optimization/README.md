# RTSA 渲染与显示性能资料索引

本目录用于记录 RTSA 上位机的渲染路径、性能证据和后续优化方案。文档中的性能数字必须区分以下三种性质：

- **源码现状**：可以直接从当前仓库代码核对的行为；
- **历史测试**：过去在 PC 或其他环境中得到的记录，不能直接代表当前版本或 ZU47DR 板端；
- **待验证项**：需要在目标板、目标 PetaLinux/BSP、目标 Qt 部署环境中复现的项目。

当前结论不是“已经达到固定 FPS”，而是：渲染路径已经采用若干降低主线程负担的措施，板端实际帧率、显示管线开销和 GPU/QPA 条件仍待按本文档的方法核验。

## 当前实现概览

根据当前源码，频谱和瀑布图的主要路径如下：

1. **频谱图采用 CPU Raster 路径**
   - `RasterSpectrumRenderer` 将网格、坐标轴和静态文字缓存到 `QImage::Format_RGB16` 静态层；
   - 每帧目标图同样使用 `Format_RGB16`；普通帧只恢复绘图区静态背景，再绘制频谱折线和标记。

2. **频谱离屏渲染使用单个工作线程**
   - `SpectrumPlotWidget` 维护一个后台工作线程和最新的 `RenderContext`；
   - 新帧到来时覆盖尚未处理的旧上下文，避免为每一帧排队；
   - 前台图与后台工作图通过 `QImage::swap()` 做 Ping-Pong 交换，避免写时复制；
   - 工作线程完成整幅图像后，通过队列通知主线程；
   - 主线程只按 `QPaintEvent` 的脏矩形执行 `drawImage()` 切片；
   - 离屏图像尚未就绪时，`paintEvent()` 会退回同步 Raster 绘制以保证首帧和单元测试可用。
   - 可通过 `--render-mode direct|offscreen` 做同板 A/B 对比，并通过
     `--display-fps 30|60|100` 限制显示刷新频率。

3. **当前没有以下实现**
   - 没有频谱处理线程池；
   - 没有 CPU 亲和性设置，也没有“CPU0/1/2 分担渲染”的源码证据；
   - 没有基于 OpenGL 的已验证频谱渲染路径；
   - 没有已证实的板端 60 FPS、固定延迟或固定 CPU 占用率。

4. **瀑布图使用 CPU 索引色环形缓冲区**
   - 历史数据采用 `QImage::Format_Indexed8`；
   - 环形缓冲区按新帧写入单行，绘制时分成两个源矩形处理跨越环形边界的数据；
   - 背景、坐标文字和色标已缓存到独立 RGB16 静态层；
   - 该实现不等于“零拷贝”或“零转换”，实际显示开销仍需在板端测量。

更完整的源码事实和验证边界见 [渲染优化方案与验证计划](./RENDER_OPTIMIZATION_PLAN.md)。

### [渲染优化方案与验证计划](./RENDER_OPTIMIZATION_PLAN.md)

说明当前已实现的离屏渲染路径、性能瓶颈的判断方法、候选优化方向、PC 历史结果的证据边界，以及可重复的板端验收步骤。所有 FPS、延迟和优化收益都应附带测试环境与原始记录；没有记录时只能作为假设。

## 建议的核验顺序

1. 在目标板确认系统版本、Qt 版本、QPA 插件、屏幕分辨率和 Framebuffer/DRM 节点；
2. 用固定源参数和固定窗口尺寸运行同一版本的 RTSA；
3. 记录输入帧率、显示帧率、`lastPaintMilliseconds()`、显示 P95 延迟、丢弃/跳过帧和 CPU 分布；
4. 分别测试纯频谱、纯瀑布图和频谱+瀑布图三种视图；
5. 如果确认存在可用的 GPU/EGL/DRM 能力，再单独验证显示管线；否则直接以当前 CPU Raster 路径做可重复基准。

## 证据边界

| 结论 | 当前可用的证据 | 使用方式 |
| :--- | :--- | :--- |
| CPU Raster、静态层、离屏工作线程 | 当前源码 | 可作为实现现状 |
| PC 上曾达到过某个 FPS 或 P95 延迟 | 历史测试记录 | 必须标注 PC、构建类型和测试日期，不能外推板端 |
| ZU47DR 的实际 GPU/QPA 能力 | 需要板端命令和运行日志 | 不能仅凭芯片系列、网上资料或文档推断 |
| 板端优化收益 | 需要同版本前后对比 | 未复现前只能写为候选方案的预期 |
| 24 小时稳定性、绝对幅度标定 | 需要长稳记录和标定数据 | 不能写成已完成 |
