# RTSA 工程实现专题

本目录用于说明项目中较容易被概括错误的几个实现点，不再把设计目标、历史测量和板端结论混在一起。

文档统一使用以下状态口径：

| 状态 | 含义 |
|---|---|
| 已实现 | 当前仓库源码中可以定位到对应代码和路径 |
| PC 历史验证 | 过去在 Windows/Qt 6 或离屏测试中取得过结果，但本次文档整理未复测 |
| 板端待验 | 需要 ZU47DR、目标 rootfs、真实 PL/DMA 数据和目标 QPA 实测 |
| 协议/标定待确认 | 依赖 PL 数据语义、绝对标定或系统方案冻结 |

## 阅读边界

- “已实现”只说明仓库中存在对应机制，不等于 ZU47DR 板端已经达到某个 FPS、延迟或稳定性指标。
- 历史性能数字必须同时写明平台、日期、测试集、分辨率和测量方法，不能跨平台外推。
- 当前测试集为 15 项。仓库历史记录中的 `14/14` 是 2026-07-26 旧测试集结果，不包含后来加入的 `rtsa_waterfall_tests`。
- 真实 DMA 吞吐、丢帧、端到端延迟、缓存一致性、绝对幅度标定和 24 小时长稳仍属于板端或协议待确认事项。
- 渲染优化资料中的早期板端数字如果缺少原始日志和可重复步骤，只能视为线索，不能作为验收证据。
