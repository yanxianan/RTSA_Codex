# RFSoC ZU47DR 实时频谱分析仪用户说明

## 1. 文档范围

本文面向安装、配置和操作 RTSA 上位机的用户与联调人员，说明当前界面的实际功能和限制。

当前软件包含：

- Windows / Qt 6 模拟数据版本；
- 与 PC 版共用的 Qt Widgets 界面；
- Linux 用户态 DMA 数据源；
- Linux dmaengine 环形缓冲驱动；
- 频谱、瀑布图、轨迹、Marker、CSV、PNG、场景、日志和配置功能。

需要特别区分：

- 模拟数据链路已在 PC 上做过自动测试和历史性能验证；
- PetaLinux/Qt 5.15 交叉编译、ZU47DR 板端显示和真实 DMA 数据尚未形成最终验收记录；
- DMA 载荷目前没有版本化帧头，Center/Span/bin count 等元数据主要由用户态配置提供；
- 当前界面没有“区间峰值”或“信道功率”按钮。对应核心计算类存在并有单元测试，但尚未提供 GUI 入口；
- 未完成射频链路标定前，dBFS 不能解释为准确 dBm。

## 2. 安装与启动

### 2.1 Windows 完整安装目录

执行安装后，程序位于安装目录的 `bin/rtsa_app.exe`。例如：

```text
build\install\bin\rtsa_app.exe
build\install\share\rtsa\config\
```

Windows 安装默认调用 `windeployqt`，在 `bin` 下部署 Qt DLL、编译器运行库和
`platforms/qwindows.dll`。交付或移动时必须保留整个安装目录，不能只复制 EXE，也不能改变插件子目录的相对位置。

### 2.2 常用命令行

```powershell
# 默认模拟数据源
.\rtsa_app.exe --source simulated

# 全屏启动
.\rtsa_app.exe --source simulated --fullscreen

# 加载默认模拟场景
.\rtsa_app.exe --source simulated `
  --scenario .\share\rtsa\config\default-simulation.json

# 自动采集 3 秒后正常退出
.\rtsa_app.exe --source simulated --smoke-test-ms 3000

# 查看全部参数
.\rtsa_app.exe --help
```

`--source` 接受 `simulated` 或 `dma`。`--scenario` 只能与模拟源一起使用。Windows 上选择 `dma` 会明确报平台不支持；Linux 上若设备或驱动不可用也会返回创建失败，不会静默切换到模拟数据。

### 2.3 启动后检查

1. 确认右侧“数据源类型”为预期类型。
2. 确认状态为“已初始化”或“已停止”。
3. 点击“开始/继续”或“单次”。
4. 检查频谱和瀑布图是否更新。
5. 查看底部状态栏的输入 FPS、显示 FPS、数据率、丢帧和延迟。

## 3. 主界面

主窗口左侧是频谱/瀑布显示区，右侧是固定宽度、可滚动的参数栏，底部状态栏显示运行诊断。

右侧参数分为四个标签页：

| 标签页 | 主要用途 |
|---|---|
| 频率与幅度 | 数据源、Center/Span、Start/Stop、频点数、帧率、幅度范围、Auto Set、全屏 |
| 模拟信号源 | 噪声、固定信号、扫频、瞬态；仅在模拟源支持时出现 |
| 迹线与瀑布 | 轨迹模式、平均次数、显示视图、瀑布色表、历史深度、清空瀑布 |
| 标记 | M1～M4、峰值搜索、门限、Delta、Marker 转中心 |

文件操作位于菜单栏：

- “文件 → 导出频谱 CSV”；
- “文件 → 保存屏幕截图”；
- “文件 → 保存模拟场景”；
- “文件 → 退出”。

显示与视图操作位于“显示”菜单。帮助菜单提供快捷键、操作指南和版本信息。内置操作指南中的少量文字可能滞后于当前代码，界面功能应以本文和实际控件为准。

## 4. 数据源与采集

### 4.1 模拟源

模拟源用于功能演示、自动测试和 PC 性能基线。界面可设置：

- 噪声底和噪声起伏；
- 两个固定信号的启用、相对中心频率、幅度和带宽；
- 扫频启用、方向、起止偏移、周期和幅度；
- 瞬态概率、幅度和持续时间；
- 固定随机种子，保证相同配置可重复。

固定信号实际频率为：

```text
信号频率 = Center + 相对中心频率偏移
```

### 4.2 DMA 源

Linux 下 `DmaSpectrumSource` 打开 `/dev/rtsa_dma`，通过 `mmap` 映射驱动环形区，并使用 `poll` 和 ioctl 启停、取出和归还槽位。

当前默认参数：

| 参数 | 默认值 |
|---|---:|
| 设备节点 | `/dev/rtsa_dma` |
| 频点数 | 1,024（固定） |
| 默认 Span | 9.765625 MHz（CIC=8/HB=2） |
| 最大 Span | 312.5 MHz（CIC=1/HB=0 旁路） |
| UI 发布速率 | 约 60 FPS |
| 帧格式 | 64 B V1 帧头 + 1024 × int16 |
| 帧长 | 2112 B |

驱动提供 128 个槽位，每槽 132 KiB，总计约 16.5 MiB。用户态每轮 `poll` 最多处理 64 个已完成槽位。

设备载荷由 `SpectrumFrameCodec` 解析：

```text
magic = 0x52545341
frame_bytes = 2112
bin_count = 1024
payload = little-endian int16，0.01 dB/LSB
```

界面修改参数后会自动通过 `rtsa_regs` UIO 下发，不需要手动 commit，也不需要停止 DMA。Center/Span 会写入帧头元数据；实际 RF 中心频率在 RFADC 模式下由固定 NCO 1.7 GHz 决定。

宽带试验模式：

```text
CIC = 1（旁路）
HB = 0
Span = 312.5 MHz
bin = 305.18 kHz
RBW ≈ 580 kHz
建议 Max Hold ≥ 16
```

### 4.3 采集控制

| 按钮 | 行为 |
|---|---|
| 开始/继续 | 从停止状态启动连续采集，或从暂停状态恢复 |
| 单次 | 生成并发布一帧后停止 |
| 暂停/继续 | 暂停新帧，保留最后有效频谱、轨迹和 Marker |
| 停止 | 停止数据源并回收采集工作线程 |

按钮会根据当前状态启用或禁用。禁用表示该操作在此时不适用。

## 5. 频率、频点与幅度

### 5.1 Center/Span 与 Start/Stop

- Center 是显示频段中心；
- Span 是完整显示带宽；
- `Start = Center - Span/2`；
- `Stop = Center + Span/2`；
- 修改任一组并提交后，另一组同步更新；
- Stop 必须大于 Start；
- “常用频宽”提供 10 MHz、20 MHz、50 MHz、100 MHz、200 MHz、500 MHz、1 GHz 和全频宽快捷按钮。

输入框获得焦点后使用滚轮可微调；未获得焦点时滚轮不会误改数值。

### 5.2 频点数

可选 1,024、2,048、4,096、8,192、16,384、32,768 和 65,536。

频点数越高，频率分辨率越高，同时每帧数据量、处理和内存带宽需求也越高。频点数、频率范围或幅度单位变化后，不兼容的平均或保持轨迹会自动清空。

### 5.3 输入帧率

- 模拟源限速范围为 1～1,000 FPS；
- GUI 不排队绘制每一个输入帧，只显示刷新时刻的最新完整帧；
- 输入 FPS 高于显示 FPS 是正常现象；
- “无等待压测”让模拟线程尽可能快地产帧，会显著占用 CPU；
- 无等待模式下输入帧率控件禁用，但保留显示值。

### 5.4 幅度显示

- 参考电平：纵轴顶部；
- 底部电平：纵轴底部，必须低于参考电平；
- 垂直刻度：每格 dB 数；
- Auto Set：根据当前有效轨迹设置合适的上下边界；
- 当前模拟默认单位为 dBFS。

## 6. 模拟信号设置

### 6.1 噪声

- 噪声底范围由界面限制，常用默认值为 -110 dBFS；
- 噪声起伏增加每个频点的随机波动；
- 固定随机种子和配置可重复产生数据序列。

### 6.2 固定信号

两个固定信号可独立设置：

- 启用状态；
- 相对 Center 的频率偏移；
- 幅度；
- 等效带宽，单位 bins。

信号和噪声在内部按线性功率合成，不是直接相加两个 dB 数值。

### 6.3 扫频

- 支持向上、向下和往返方向；
- 起止点用相对 Center 的 MHz 偏移表示；
- 起点必须小于终点；
- 周期范围为 0.1～3,600 秒；
- 往返模式到达终点后反向移动。

### 6.4 瞬态

- 概率以每帧百分比表示；
- 幅度单位为 dBFS；
- 持续时间为 0.001～60 秒；
- 一次触发后在持续期间保持同一频率。

将瞬态概率设为 `0` 可关闭瞬态。

### 6.5 默认演示效果

默认配置为 1 GHz Center、200 MHz Span、16,384 点、200 FPS、-110 dBFS 噪声、两个固定峰和一条扫频线。开始采集后应能看到噪声底、两个固定峰和移动的扫频峰。

## 7. 频谱与瀑布图操作

### 7.1 显示视图

“迹线与瀑布”页和“显示 → 视图模式”均提供：

- 仅频谱图；
- 仅瀑布图；
- 频谱+瀑布图。

默认使用双视图。瀑布图使用 `Format_Indexed8` 环形缓冲并向主窗口提交每一帧。

### 7.2 鼠标

| 操作 | 结果 |
|---|---|
| 单击频谱 | 将当前活动 Marker 设置到该频率 |
| 滚轮向上 | 以指针位置为中心缩小 Span |
| 滚轮向下 | 扩大 Span |
| 左键拖动 | 水平平移频率范围 |
| Shift + 左键拖动 | 框选频率范围并缩放 |
| 双击 | 恢复用户设置的完整频率范围 |

瀑布图使用相同的缩放、平移和框选语义。

### 7.3 键盘

先让绘图区获得焦点：

| 按键 | 功能 |
|---|---|
| `Home` 或 `R` | 恢复完整频率范围 |
| `+` 或 `=` | 放大 |
| `-` | 缩小 |
| `←` / `→` | 向低频/高频平移当前 Span 的约 10% |
| `M` | 活动 Marker 峰值搜索 |
| `F5` | Auto Set |
| `F11` | 全屏切换 |
| `Ctrl+G` | 显示/隐藏网格 |
| `Ctrl+E` | 导出 CSV |
| `Ctrl+S` | 保存频谱截图 |
| `Esc` | 退出全屏 |

### 7.4 触摸

- Pinch 缩放 Span；
- Pan 平移中心频率；
- 触摸逻辑已有 Qt 事件测试，实际手感需在目标屏确认。

## 8. 轨迹与瀑布设置

### 8.1 轨迹

| 模式 | 说明 |
|---|---|
| Clear/Write | 使用最新频谱覆盖旧频谱 |
| Average | 对最近 N 帧平滑，N 为 1～1,024 |
| Max Hold | 保存每个频点历史最大值 |
| Min Hold | 保存每个频点历史最小值 |

“清除历史轨迹”重置 Average、Max Hold 或 Min Hold 的历史。

### 8.2 瀑布图

- 历史深度 64～2,048 行，默认 512 行；
- 可清空当前瀑布历史；
- 历史缓冲满后使用两段环形切片绘制，避免每次滚动都整图搬移；
- 五色调色板可在“迹线与瀑布”页或“显示 → 瀑布图色图”中切换；
- 频谱显示和瀑布图共享当前频率范围，但暂不共享同一鼠标悬停读数。

## 9. Marker 与峰值搜索

### 9.1 M1～M4

1. 在“标记”页选择活动 Marker。
2. 单击频谱，或直接输入 Marker 频率。
3. 当前读数卡片显示频率、幅度和相对 M1 的差值。
4. 多 Marker 表同时列出 M1～M4 的状态和读数。

Marker 按频率保存位置。新帧到达后幅度自动更新；频率移出当前 Span 后显示无效。

### 9.2 峰值搜索

- “峰值门限”过滤低幅度局部峰；
- “搜索峰值”把活动 Marker 放到完整频谱的最大峰；
- “上一个峰值”和“下一个峰值”在满足门限的相邻局部峰之间移动；
- 搜索使用完整频点，不使用屏幕压缩后的包络点。

若没有结果，先降低门限，并确认已有有效帧和正确频率范围。

### 9.3 Delta 与清除

- M1 是 Delta 的基准；
- 活动 Marker 为 M2～M4 时显示相对 M1 的频差和幅差；
- “清除当前”只清除活动 Marker；
- “清除全部”清除 M1～M4；
- 可将活动 Marker 频率转换为中心频率。

## 10. 文件与数据

### 10.1 保存 PNG

使用“文件 → 保存屏幕截图”或 `Ctrl+S`。截图来自 CPU Raster 频谱控件，只包含频谱坐标、网格、轨迹和 Marker，不包含瀑布图和右侧参数面板。

### 10.2 导出 CSV

获得至少一帧有效数据后，使用“文件 → 导出频谱 CSV”或 `Ctrl+E`。

CSV 包含：

- 帧序号和单调时钟时间戳；
- Center、Span 和频点数；
- 幅度单位和标定状态；
- 每个频点的索引、频率和幅度。

导出对象是点击时的不可变完整帧快照，后台线程写入，并使用原子文件提交。失败时不会留下看似完整的半写文件。

### 10.3 保存模拟场景

使用“文件 → 保存模拟场景”把当前模拟参数保存为 JSON。场景包括频率、点数、帧率、噪声、固定信号、扫频、瞬态和故障设置。

保存前会执行与加载相同的完整校验；保存使用原子提交。命令行加载的场景优先于已保存的模拟设置。

安装目录通常提供：

| 文件 | 用途 |
|---|---|
| `default-simulation.json` | 默认功能演示 |
| `unthrottled-stress.json` | 16,384 点无等待压力测试 |
| `fault-injection.json` | 暂停、序号跳变、NaN 异常帧和突发故障 |

场景版本为 v2，兼容 v1；文件上限 1 MiB，最多两个固定信号。

## 11. 状态与诊断

| 指标 | 含义 |
|---|---|
| 状态 | 数据源生命周期状态 |
| 输入速率 | 数据源生成/交付帧的速率 |
| 显示速率 | GUI 实际显示不同帧的速率 |
| 输入数据率 | 完整频谱数据的平均吞吐率 |
| 源/传输丢帧 | 数据源未形成或未交付的帧 |
| 无效帧 | 点数、数值或元数据校验失败的帧 |
| 处理丢帧 | 轨迹处理阶段未发布的帧 |
| 发布/提交 | 流水线发布数和数据源提交数 |
| 显示跳过/已显示 | GUI 主动跳过的旧帧和真正显示的帧 |
| 帧龄 | 当前可见帧从产生到显示的时间 |
| 显示延迟 P95 | 最近 256 个实际绘制完成样本的 95 分位 |
| 处理耗时 | 单帧校验和轨迹处理时间 |
| 绘制耗时 | CPU Raster 绘制时间 |
| 处理队列深度 | 最新帧架构下同步等待队列深度，正常为 0 |
| 最近错误 | 最近一次数据源或处理错误 |

状态区还提供“引擎遥测”入口，可打开独立诊断窗口。输入 FPS 高于显示 FPS 是实时显示优先策略的结果，不代表数据源故障。

## 12. 配置与日志

### 12.1 配置

程序正常退出时保存窗口、频率范围、频点数、帧率、模拟参数、幅度、轨迹和 Raster 外观设置。格式为 v4，兼容较早版本；损坏、越界或未知版本会整体回退到安全默认值。

- Windows：Qt 原生用户设置存储；
- Linux：通常为应用本地配置，例如 `~/.config/RTSA/RTSA.conf`。

### 12.2 日志

```powershell
.\rtsa_app.exe `
  --log-dir D:\RTSA-Logs `
  --log-level info `
  --log-max-bytes 5242880 `
  --log-retained-files 3
```

- `--log-level`：`debug`、`info`、`warning`、`error`；
- `--log-max-bytes`：至少 1,024 字节；
- `--log-retained-files`：1～10；
- `--no-file-log`：关闭文件日志，主要用于自动测试。

日志使用 UTC 时间，当前文件为 `rtsa.log`，轮转文件为 `rtsa.log.1`、`rtsa.log.2` 等。

## 13. Linux 与 DMA 联调

### 13.1 启动顺序

1. 配置并加载 PL bitstream。
2. 确认设备树包含 DMA 节点和 `dma-names = "rx_chan"`。
3. 编译并加载 `rtsa_dma.ko`。
4. 确认 `/dev/rtsa_dma` 存在且有读写权限。
5. 启动应用并选择 `--source dma`。
6. 先使用低速固定图样验证帧边界、点数、字节序和数值范围。
7. 再接入真实 DDC/FFT 输出并做吞吐、丢帧、延迟和标定。

驱动构建示例：

```sh
make -C driver/DMA \
  KDIR=/path/to/linux-xlnx \
  ARCH=arm64 \
  CROSS_COMPILE=aarch64-linux-gnu-
```

### 13.2 显示后端

无 GPU 的 linuxfb 环境可尝试：

```sh
export QT_QPA_PLATFORM=linuxfb
export QT_QPA_FB_HIDECURSOR=1
./rtsa_app --source simulated --fullscreen
```

若 rootfs 使用 X11、XCB 或 Wayland，应改用对应 QPA。程序本身始终使用 CPU Raster，不需要 OpenGL 上下文。

## 14. 常见问题

| 现象 | 处理 |
|---|---|
| 缺少 `Qt6Core.dll`、`Qt6Widgets.dll` 等 | 使用完整安装目录，不要只复制 EXE |
| 找不到 Qt platform plugin | 检查 `bin/platforms/qwindows.dll` 及目录结构 |
| 右侧输入框文字不清晰 | 确认使用当前版本；应用使用 Fusion 高对比度主题 |
| 点击开始后无频谱 | 检查数据源状态和“最近错误”，恢复默认模拟场景后重试 |
| CSV 菜单不可用 | 先开始采集或执行单次采集，确保已有完整帧 |
| 峰值搜索无结果 | 降低门限，确认目标在 Span 内且有有效帧 |
| 输入 FPS 高、显示 FPS 低 | 正常的最新帧显示策略，不是输入丢帧 |
| 无等待模式 CPU 很高 | 预期行为；关闭无等待并恢复限速 |
| `WrapVulkanHeaders` 缺失 | Qt 可选探测提示；项目不使用 Vulkan/OpenGL |
| `--source dma` 创建失败 | 检查平台、`/dev/rtsa_dma`、权限、驱动加载和设备树 |
| DMA 数据幅度异常 | 检查帧头 magic/version/bin_count、payload int16、标定偏移和 epoch |
| linuxfb 无文字 | 检查 rootfs 字体、fontconfig 和 Qt 插件依赖 |

## 15. 已知限制

- 当前 GUI 没有区间峰值/信道功率控件；
- PNG 和 CSV 不包含完整瀑布历史；
- DMA 已使用 V1 版本化帧头；312.5 MHz 模式下 1024 点 FFT 的 RBW 约 580 kHz；
- PL 输出是每 bin 功率还是 PSD 尚未冻结，RBW/ENBW 未进入统一帧模型；
- 绝对 dBm 标定尚未完成；
- PetaLinux/Qt 5.15 实际构建和板端长稳仍待验收；
- 内置“操作指南”对话框的部分文案由源码生成，其中个别旧描述可能尚未与当前 UI 完全同步。

协议、驱动和板端验收细节见[总体实现架构与设计方案](../design/实时频谱分析仪软件总体实现架构与设计方案.md)、[DMA 数据源接口与 PL/PS 协议](../design/DMA数据源接口与PL_PS协议确认清单.md)和[DMA 驱动解析](DMA驱动解析.md)。
