## 1. 文档定位与状态定义

本文描述仓库当前已经形成的软件架构，不再沿用早期“独立处理线程、SPSC 队列、四核线程池、一期不接 DMA”等规划口径。需求背景和验收拆分见《实时频谱分析仪软件需求规格说明书》，硬件联调差距见《ZU47DR_PL/AXI DMA 频谱数据接入差距分析与后续实施方案》。

文档使用四类状态：

- **已实现**：当前源码中存在对应类和调用路径；
- **PC 历史验证**：有过去的 Windows PC 测量记录，但本次未复测；
- **板端待验**：尚未在目标 ZU47DR、PetaLinux、Qt 5 和真实 DMA 环境形成结论；
- **协议/标定待确认**：依赖 PL、驱动、系统或标定输入，不能由当前模拟结果证明。

## 2. 目标与非目标

### 2.1 当前目标

- 使用 Qt Widgets 和 C++17 构建桌面式实时频谱分析仪；
- 在 PL 输出频谱结果的前提下，由 PS 端负责接收、转换、跟踪、显示和导出；
- 使用 CPU Raster 路径，不依赖 OpenGL、EGL 或 GPU 驱动；
- 同时支持模拟源和 Linux DMA 用户态源；
- 通过统一 `SpectrumFrame` 将数据源、处理、绘图和文件功能隔离；
- 保持 Qt 6 与 Qt 5.15 API 的源码兼容方向，为目标 PetaLinux 移植留出空间。

### 2.2 当前非目标

- 不在 PS 端执行原始 ADC/IQ 的大点数 FFT；
- 不在本仓库内实现 PL 的 DDC、窗函数、FFT 或射频前端；
- 不把模拟源性能等同于真实 DMA、DDR 和 AArch64 性能；
- 不在绝对标定完成前宣称 dBm、RBW、PSD 或信道功率具备计量可信度；
- 不把 linuxfb、Qt 5、ARM64、24 小时长稳或硬件端到端延迟写成已完成事项。

## 4. 运行数据流

### 4.1 模拟源路径

```text
SimulatedSpectrumSource 采集线程
  -> FrameSink
  -> SpectrumPipeline::submit()
  -> 帧校验 + TraceProcessor 更新 + LatestFrameStore 发布
  -> MainWindow 定时读取最新帧
  -> SpectrumPlotWidget / WaterfallPlotWidget
```

模拟源直接生成 FFT 后的 `float32` 频谱值，不生成 ADC 时域数据，也不执行 PS 端 FFT。该路径用于验证显示、轨迹、交互和文件功能，不能证明真实 PL 频谱链路。

### 4.2 DMA 源路径

```text
PL AXI4-Stream
  -> AXI DMA S2MM
  -> Linux dmaengine 驱动
  -> /dev/rtsa_dma
  -> mmap + poll + ioctl
  -> DmaSpectrumSource 采集线程
  -> SpectrumFrameCodec 解析 64 B 帧头 + int16 dBFS
  -> FrameSink
  -> SpectrumPipeline::submit()
  -> LatestFrameStore
  -> GUI
```

当前 DMA 载荷是 V1 版本化帧：Magic、version、frame bytes、sequence、timestamp、Center/Span、bin count、窗函数、校准、格式和 config epoch。帧序号和时间戳同时在帧头和驱动槽位信息中提供。

### 4.3 控制面

当前 GUI 参数通过 `DmaSpectrumSource::setConfiguration()` 写入 `rtsa_regs` staging，再写 `0x120 COMMIT`。PL 在当前频谱帧结束后锁存 active 配置；软参数只换帧头，DDS/CIC/HB 由 PL 内部重配。配置 epoch 随帧头返回，DMA 不停机。

## 5. 线程、缓冲与所有权

### 5.1 线程

| 执行体 | 当前职责 |
|---|---|
| GUI 主线程 | Qt 事件、界面更新、取得最新帧、最终 `paintEvent()` 贴图 |
| 模拟采集线程 | 生成模拟频谱并按配置速率发布 |
| DMA 采集线程 | 等待 DMA 槽位、转换原始数据、发布频谱帧 |
| 单个离屏渲染线程 | 在后台生成频谱 RGB16 目标图 |

模拟源和 DMA 源均在自己的采集线程中直接调用 `SpectrumPipeline::submit()`。管线在该调用线程同步完成校验、轨迹处理和最新帧发布，因此当前没有独立处理线程，也没有线程池或四核负载均衡。

### 5.2 最新帧发布

`LatestFrameStore` 使用原子 `std::shared_ptr<SpectrumFrame>` 保存最新完整帧。GUI 的显示刷新定时器周期为 10 ms，只读取当前可取得的最新帧；输入帧率高于显示帧率时，旧帧会被覆盖，不做历史显示排队。统计定时器周期为 500 ms。

### 5.3 帧池

- 模拟源使用 `FramePool`，默认上限为 8；
- `DmaSpectrumSource` 内部帧池上限为 64；
- 帧池用于复用 `SpectrumFrame` 对象，不是处理队列；
- 当前 `queueDepth` 固定为 0，不应解释为 DMA 环槽或待处理帧数量。

### 5.4 所有权规则

1. 数据源发发布完整 `SpectrumFrame`，消费者只读访问；
2. `LatestFrameStore` 保证 GUI 获取到的是完整帧，而不是半帧或裸 DMA 缓冲；
3. DMA 原始槽位在转换完成后归还驱动；
4. GUI 和绘图对象不得长期持有 DMA 映射内存；
5. Stop、Error、超时和解析失败路径都必须归还已取得的槽位；
6. 当前转换会发生一次从 DMA 载荷到内部 `float32` 的复制/换算，尚未实现外部内存零拷贝。

## 6. 模拟源与 DMA 源

### 6.1 统一数据源接口

`ISpectrumSource` 提供：

- `start(Continuous)`；
- `start(SingleFrame)`；
- `pause()`；
- `resume()`；
- `stop()`；
- `state()`；
- `statistics()`；
- `FrameSink` 帧发布回调。

模拟源和 Linux DMA 源都实现该接口，因此频谱控件、轨迹、Marker、CSV 和配置模块不需要感知数据来源。

### 6.2 模拟源

`SimulatedSpectrumSource` 支持噪声底、单音、多音、扫频、瞬态和预设场景。它可按配置生成 1,024～65,536 点频谱，并把帧直接提交给同步管线。固定随机种子用于可重复测试。

### 6.3 DMA 用户态源

当前 `DmaSpectrumSource` 的关键事实：

- 仅 Linux 构建；
- 默认设备 `/dev/rtsa_dma`；
- 固定 1,024 bins，span 由 CIC/HB 决定；
- 解析 V1 帧头，payload 为 int16 对数幅度；
- 使用 `open`、`mmap`、`poll` 和 `ioctl`；
- UAPI 定义 128 个 132 KiB 槽位，共约 16.5 MiB；
- 支持 `RTSA_IOC_SET_FRAME_SIZE` 和 `RTSA_IOC_GET_STATS`；
- 每轮 `poll` 最多处理 64 个完成槽位；
- 发布速率节流约 60 FPS；
- 通过 `PlRegisterMap` 运行中下发参数，`eventfd` 唤醒；
- 使用 `config_epoch` 过滤旧帧；
- `start(SingleFrame)` 在取得有效帧后停止；
- 输出标记 `calibrated=false`。

### 6.4 DMA 驱动基线

`rtsa_dma_driver.c` 使用 `dma_alloc_coherent` 分配槽位，compatible 为 `rtsa,spectrum-dma`，DMA 名为 `rx_chan`。完成队列溢出时驱动会重新提交槽位，但这只能说明存在恢复机制，不能据此宣称绝不丢帧。

## 7. 频谱渲染与瀑布

### 7.1 频谱 Raster 路径

- `SpectrumPlotWidget` 使用 Qt Raster `QPainter`；
- 坐标轴、网格、标签等静态层缓存为 `QImage::Format_RGB16`；
- 离屏目标图同样使用 RGB16；
- 后台只有一个 `std::thread` 渲染 worker；
- 新 `RenderContext` 覆盖尚未处理的旧上下文；
- 主线程 `paintEvent()` 只把完成的目标图按脏区 `drawImage` 到控件；
- 离屏结果尚未就绪时，主线程使用同步 Raster 路径兜底。

源码中的部分历史注释仍可能出现“CPU0/1/2”“多核异步”等表述，这些不是当前实现事实。

### 7.2 包络降采样

`EnvelopeReducer` 按屏幕像素列统计覆盖频点的最小值和最大值。这样可保留窄峰信息，并让绘制复杂度随屏幕宽度收敛。当前实际绘制连接各列最大值形成折线；最小值已经计算，但尚未绘制为最小—最大垂直包络。

Marker 和核心测量使用完整频点数据，不使用屏幕上降采样后的折线。

### 7.3 瀑布图

`WaterfallPlotWidget` 使用 `QImage::Format_Indexed8`：

- 历史深度 64～2,048 行，默认 512；
- 五种色表；
- 新频谱行写入环形缓冲；
- 缓冲写满后用双切片绘制，避免整块历史搬移；
- 清空操作重置写指针和历史内容。

瀑布测试目标 `rtsa_waterfall_tests` 已注册，但本次文档整理未执行测试。

### 8.2 测量

## 9. 构建、部署与测试

### 9.1 构建

- 语言：C++17；
- UI：Qt Widgets；
- 构建系统：CMake；
- PC 当前以 Qt 6 开发和验证；
- 目标方向为 Qt 5.15.x，实际版本由 PetaLinux SDK/rootfs 决定；
- 当前没有形成 Qt 5 构建通过的验收记录。

当前 CMake 选项只有：

- `RTSA_BUILD_TESTS`；
- `RTSA_ENABLE_WARNINGS_AS_ERRORS`；
- `RTSA_TARGET_PETALINUX`；
- `RTSA_DEPLOY_WINDOWS_RUNTIME`。

不存在 `RTSA_ENABLE_DMA_SOURCE`。

### 9.2 目标部署

linuxfb 启动示例可参考 DMA 部署文档，但其中命令属于现场操作记录，不代表当前版本已在板上验证。目标 rootfs 至少需要 Qt Core/Gui/Widgets、QPA 插件、字体以及应用使用的图像格式支持。

### 9.3 测试

当前 CMake 注册 15 项测试，包括 `rtsa_waterfall_tests`。2026-07-26 的 Windows Qt 6 历史结果 `14/14` 对应旧测试集，不能替代当前 15 项测试结果。

历史 PC 记录中，16,384 点、请求 1,000 FPS 时：

- Debug 输入约 999.95 FPS，显示约 32.62 FPS；
- Release 输入约 1,000.01 FPS，显示约 33.70 FPS；
- 显示延迟 P95 约 16.5 ms。

这些数据仅证明当时的 Windows PC 模拟路径，不外推到 ZU47DR。

## 10. 已验证、待验和风险

### 10.1 当前 PC 验证

- 频谱、轨迹、Marker 和状态显示；
- 16,384 点、约 1,000 FPS 模拟输入；
- 最新帧优先显示；
- Debug/Release 构建和旧测试集；
- C++/Qt CTest 20/20；
- PL 控制链、CIC 旁路和 312.5 MSPS FFT 吞吐定向仿真通过。

### 10.2 板端/外部待验

- V1 帧头、TLAST、帧边界、字节序和 `info.size` 的板端实测；
- 真实 DMA 吞吐、丢帧、缓存一致性和复位恢复；
- 312.5 MHz 宽带模式的持续帧率、`frame_drop_count` 和 FFT FIFO 状态；
- Qt 5.15.x、PetaLinux SDK、AArch64 交叉构建；
- linuxfb/XCB 等 QPA、屏幕、字体和触摸；
- 幅度标定、RBW、PSD 和信道功率物理语义；
- 24 小时长稳和端到端延迟。

### 10.3 主要风险

| 风险 | 影响 | 当前控制 |
|---|---|---|
| 312.5 MHz + 1024 点 FFT 的 RBW 约 580 kHz | 宽带下分辨率不足 | 后续增加 FFT 点数或信道化 |
| 312.5 MHz 使用 0% 重叠 | 帧率和组帧跳过增加 | 当前以 Max Hold 80 降低 DMA 帧率，板端观察 |
| GUI 无区间测量入口 | 核心计算能力无法由用户直接使用 | 后续单独设计测量面板 |
| 单离屏 worker 可能成为高分辨率瓶颈 | 高负载时显示 FPS 下降 | 保留最新上下文和同步兜底，后续实测再决定是否并行 |
| 绘制只使用最大值折线 | 最小值包络未可视化 | 若产品需要 min/max 包络，再完善渲染 |
| Qt 5 和板端未验证 | 目标构建或 QPA 启动失败 | 建立 SDK、交叉构建和 linuxfb 验收流水线 |
| 绝对幅度未标定 | 数值不能作为绝对功率依据 | 保持 `calibrated=false`，冻结标定公式后再启用 |
