## 1. 文档目的

本文档定义运行于 RFSoC ZU47DR PS 端 Linux 系统中的实时频谱分析仪软件需求，作为软件设计、编码、测试、交叉编译、部署及后续 PL/PS 联调的依据。

本文档保留原始一期需求编号，作为追踪矩阵的稳定基线。当前仓库已经超出最初“仅模拟源、无瀑布图”的阶段：Qt 界面、瀑布图、Linux DMA 用户态源、内核驱动、V1 帧头、UIO 实时参数控制和 312.5 MHz CIC 旁路均已实现。RBW/PSD 定义、绝对标定、PetaLinux 实际构建和 ZU47DR 板端验收仍未完成。

阅读本文时须区分：

- “一期”描述最初交付范围；
- “当前实现扩展”描述仓库中已经存在但可能尚未板端验收的能力；
- “待确认”描述阻断真实硬件验收的外部输入。

## 2. 项目背景与目标

### 2.1 项目背景

系统硬件平台为 RFSoC ZU47DR。PL 侧负责射频数据处理，包括但不限于 DDC、加窗、FFT 及频谱数据生成；PS 侧不承担大带宽原始 ADC 数据的 FFT 运算，主要负责：

- 接收 PL 产生的频谱结果；
- 将硬件数据转换为软件内部统一频谱帧；
- 实时显示频谱曲线；
- 提供常用频谱分析仪交互和测量功能；
- 显示运行状态、数据率、帧率和异常信息；
- 为瀑布图、多通道和硬件控制等后续功能预留扩展能力。

### 2.2 一期目标

1. 在 Windows PC 上完成可独立运行的模拟版软件。
2. 模拟数据源能够产生具有噪声、单音、多音、扫频和瞬态特征的频谱数据。
3. 在无 GPU 加速假设下，实现高性能、低延迟、可长期运行的实时频谱显示。
4. 软件源代码同时兼容 Qt 6.x 和 PetaLinux 2023.2 所采用的 Qt 5.15.x。
5. 建立与数据来源无关的频谱处理和显示架构。
6. 给出后续 AXI DMA 数据接入接口、协议约束和联调验收要求。
7. 完成 ARM64 目标版本的交叉编译、部署和板端运行验证。

### 2.3 长期目标

- 接入真实 AXI DMA 连续数据流；
- 增加多通道瀑布图与时间选通分析；
- 支持多通道频谱显示；
- 增加更多频域测量和告警功能；
- 根据硬件协议控制 DDC、FFT、窗函数、平均次数等 PL 参数；
- 支持频谱数据记录、回放及远程控制。

## 4. 已确认条件、设计假设与待确认项

### 4.1 已确认条件

- 软件直接运行于 RFSoC ZU47DR 的 PS 端 Linux 系统中，而非外部 PC 上位机。
- 目标 Linux 由 PetaLinux 2023.2 构建。
- PC 开发环境为 Windows，当前可使用 Qt 6.x。
- PL 负责 DDC 和 FFT，PS 接收频谱结果后显示。
- PL 与 PS 计划通过 AXI DMA 传输数据。
- 一期软件可在 PL 协议冻结前使用模拟数据完成 PC 验证。
- 当前已实现频谱/瀑布图显示、DMA 用户态源和内核驱动。
- 真实板端结论必须以目标硬件、rootfs 和 PL 输出为准。
- 屏幕暂定为 1920×1080、60 Hz。
- 项目按目标板无可用GPU或无可用GPU驱动设计，一期不依赖OpenGL硬件加速。

### 4.2 设计假设

- PS 端为 AArch64 架构，具备可运行 Qt Widgets 应用的显示输出通路。
- 目标系统至少能够提供 Linux framebuffer、X11/XCB 或其他支持 Qt Raster 绘制的 QPA 平台之一。
- PL 最终输出的是已经形成频点序列的幅度或功率数据，而非连续时域 ADC 数据。
- DMA 数据写入 PS DDR，用户态通过 `mmap + poll + ioctl` 接口取得完整槽位。
- UI 刷新率无需等于输入频谱帧率；当输入过快时允许丢弃过期的显示帧，但采集和丢帧状态必须可统计。
- 软件内部以 `float32` 表示频点显示值，默认单位为 dBFS；真实标定关系确定后允许切换为 dBm 或其他单位。

## 5. 总体技术约束

### 5.1 开发语言与构建系统

- 开发语言：C++17；
- GUI 框架：Qt Widgets；
- PC 阶段：Qt 6.x；
- 目标端：Qt 5.15.x；实际版本以目标 rootfs、PetaLinux SDK 和 meta-qt5 配方为准；
- 构建系统：CMake；
- 单元测试：Qt Test；
- 源代码编码：UTF-8；
- 默认界面语言：简体中文，频率和幅度单位采用国际通用缩写。

### 5.2 Qt 兼容要求

1. 业务代码不得依赖仅在 Qt 6 中存在且无 Qt 5 替代方案的 API。
2. Qt 5/Qt 6 API 差异必须封装在独立兼容层中，不得散布于全部业务代码。
3. CMake 应通过 `find_package(QT NAMES Qt6 Qt5 ...)` 支持双版本构建。
4. 不使用已在 Qt 6 移除的 `QRegExp` 等接口。
5. 鼠标坐标、编码、容器行为等差异应通过条件编译集中处理。
6. 每个阶段性版本至少在 Windows Qt 6 和 Qt 5.15.x 各完成一次构建验证。

### 5.3 无GPU渲染约束

1. 一期不得把OpenGL、OpenGL ES、EGL或GPU驱动作为运行前提，也不实现OpenGL渲染后端。
2. 不采用`QOpenGLWidget`、Qt Quick Scene Graph或软件OpenGL作为一期频谱绘制路径。
3. 默认采用继承自`QWidget`的自定义频谱控件和Qt Raster `QPainter`绘制。
4. 坐标轴、网格、标签等静态内容必须缓存，仅在窗口尺寸或坐标范围变化时重绘。
5. 高频频谱曲线必须按可见像素宽度做降采样后再绘制。
6. 降采样必须保留每个像素列覆盖频点的最小值和最大值，不能仅抽取单点，以免窄带峰值消失。
7. 绘制所用数组、图像和路径对象应预分配或复用，避免逐帧大量内存申请。
8. 软件架构可以保留抽象渲染接口，但GPU后端不属于一期实现和验收范围。

### 5.4 PetaLinux 与交叉编译约束

- PetaLinux 版本号不能证明 Qt 已安装；配方和实际版本取决于工程的 layer、packagegroup 和 rootfs。
- Qt 通常不是最小 rootfs 的默认组件，目标工程需显式选择 Qt5/Qt Widgets、字体、PNG 和 QPA 插件。
- 生成 Qt 交叉编译 SDK 时需确认 SDK 中包含 CMake 配置和 Qt5 Core/Gui/Widgets。
- Windows 用于本机开发和模拟测试；最终 PetaLinux SDK 生成及 ARM64 交叉编译应在受支持的 Linux 主机环境中完成。
- Linux 构建主机优先采用 PetaLinux 2023.2 文档支持的 Ubuntu 20.04.6 LTS 或 Ubuntu 22.04.2 LTS。
- 目标可执行文件不得动态依赖未加入 PetaLinux rootfs 的第三方库。

## 6. 软件总体架构

### 6.1 模块结构

```text
src/
├─ app/       进程启动与顶层异常处理
├─ ui/        主窗口、控件、主题与交互协调
├─ plot/      频谱、瀑布图和 CPU Raster 渲染
├─ core/      频谱帧、管线、轨迹、测量与最新帧发布
├─ sources/   模拟源、DMA 用户态源和数据源工厂
└─ services/  配置、日志、CSV/PNG 导出
```

### 6.2 核心模块

| 模块 | 主要职责 |
|---|---|
| Application | 进程初始化、命令行参数、日志初始化和退出流程 |
| MainWindow | 主界面布局、菜单、工具栏、状态栏和功能协调 |
| SpectrumPlotWidget | 频谱画布、网格、坐标、Marker、交互及CPU Raster绘制 |
| RasterSpectrumRenderer | CPU Raster绘制、RGB16 静态层和频谱轨迹渲染 |
| ISpectrumSource | 数据源统一接口、生命周期和状态通知 |
| SimulatedSpectrumSource | 生成可重复、可配置的模拟频谱数据 |
| DmaSpectrumSource | 封装 Linux DMA 用户态 API，不承担内核驱动职责 |
| SpectrumPipeline | 在调用线程同步完成帧校验、轨迹处理、统计和最新帧发布 |
| FramePool | 复用频谱帧对象，模拟源默认最多保留 8 个帧对象 |
| LatestFrameStore | 通过原子共享指针发布最新完整帧 |
| TraceProcessor | Clear/Write、平均、最大保持和最小保持 |
| SpectrumMeasurements | 区间峰值和信道功率核心计算；当前 GUI 未提供区间测量控件 |
| EnvelopeReducer | 按屏幕像素列计算最小/最大包络；当前曲线绘制使用各列最大值 |
| WaterfallPlotWidget | Indexed8 环形历史和双切片瀑布绘制 |
| ConfigurationStore | 配置加载、校验、原子保存和默认值恢复 |
| SpectrumExporter | PNG 截图和完整频谱 CSV 导出 |
| ApplicationLogger | 文件日志、错误状态和运行信息记录 |

### 6.3 线程模型

| 线程 | 职责 | 约束 |
|---|---|---|
| GUI 主线程 | 控件事件、布局和最终绘制 | 不得阻塞等待 DMA、文件或大批量计算 |
| 采集线程 | 模拟数据生成或 DMA 数据获取 | 通过 `FrameSink` 直接同步调用 `SpectrumPipeline::submit()`，不直接操作 GUI |
| 单个离屏渲染线程 | 将频谱内容渲染到 RGB16 目标图 | 只处理最新 `RenderContext`；新上下文会覆盖尚未处理的旧上下文 |

当前没有独立处理线程、SPSC 处理队列、线程池或四核负载均衡。采集侧调用返回后，帧校验、轨迹处理、最新帧发布和统计已完成。

### 6.4 缓冲与数据所有权

1. 频谱缓冲在启动或参数变更时预分配，稳定运行期间不得逐帧频繁申请大块内存。
2. 模拟源和 DMA 源均通过 `FrameSink` 把完整帧直接交给同步管线。
3. `LatestFrameStore` 使用原子 `std::shared_ptr` 发布最新完整帧，GUI 只读取刷新时刻可取得的最新帧。
4. 发布给 GUI 的频谱帧在消费期间必须保持只读且生命周期有效。
5. DMA 源内部帧池上限为 64；帧池只是复用容器，不构成处理队列。
6. 必须分别统计：源产生帧、源接收帧、协议错误帧、提交丢弃帧、GUI 显示帧。
7. 当前 `queueDepth` 固定为 0，不代表底层 DMA 环槽数量，也不能作为处理队列深度使用。

## 7. 内部数据模型

### 7.1 统一频谱帧

内部 `SpectrumFrame` 至少包含：

| 字段 | 建议类型 | 说明 |
|---|---|---|
| sequence | `uint64_t` | 单调递增帧序号 |
| timestampNs | `uint64_t` | 采集或生成时间戳，单位 ns |
| centerFrequencyHz | `double` | 中心频率 |
| spanHz | `double` | 当前分析带宽 |
| startFrequencyHz | `double`（派生） | 起始频率，由中心频率和 Span 计算 |
| stopFrequencyHz | `double`（派生） | 终止频率，由中心频率和 Span 计算 |
| binCount | `uint32_t` | 有效频点数 |
| amplitudeUnit | 枚举 | dBFS、dBm、dBc 或 Linear |
| flags | 位标志 | 有效性、过载、校准状态等 |
| bins | 只读 `float32` 数组 | 按频率升序排列的显示值 |

### 7.2 频点频率映射

默认采用包含起点、不重复包含终点的映射：

```text
binWidth = spanHz / binCount
frequency(i) = startFrequencyHz + i × binWidth
```

若 PL 最终协议采用其他定义，应仅修改协议适配层和映射策略。

### 7.3 幅度归一化

- 一期模拟数据内部单位为 dBFS；
- 显示有效范围默认 `-160 dBFS ～ 0 dBFS`，用户可调整；
- 真实 DMA 数据通过 `displayValue = rawValue × scale + offset` 或协议指定公式转换；
- 未完成硬件标定前，界面必须明确标注“未校准”，不得把估算值展示为准确 dBm；
- NaN、Inf 和越界值必须被检测并按无效数据处理。

## 9. AXI DMA 接入要求与当前实现

### 9.1 数据源接口要求

`DmaSpectrumSource` 已实现与模拟数据源相同的生命周期和帧发布接口。其职责包括：

- 打开和关闭用户态 DMA 设备；
- 获取已完成的 DMA 缓冲；
- 依据当前槽位实际大小和配置频点数识别载荷范围；
- 将原始频点转换为内部 `float32` 频谱帧；
- 维护帧序号、数据率、超时和错误统计；
- 在停止或错误时安全归还 DMA 缓冲。

内核驱动、中断、DMA 映射、缓存一致性和设备树由硬件/驱动提供方负责，但必须向本软件提供稳定的用户态 API 文档。

当前实现事实：

- 设备节点默认 `/dev/rtsa_dma`；
- 驱动使用 128 个 132 KiB coherent DMA 槽位，共约 16.5 MiB；
- UAPI 使用 `open`、`mmap`、`poll`、`ioctl`；
- 支持 `RTSA_IOC_SET_FRAME_SIZE` 和 `RTSA_IOC_GET_STATS`；
- 驱动返回槽索引、有效字节数、序号、完成时间戳和状态；
- 用户态每轮最多处理 64 个完成槽位，并限制 UI 发布速率约 60 FPS；
- 载荷为 64 B V1 帧头 + 1024 × little-endian `int16` 对数幅度；
- 帧头携带 Center/Span/bin count/sequence/timestamp/calibration/epoch；
- 当前 1024 点帧长 2112 B。

### 9.2 推荐的 PL/PS 协议原则

以下为建议，尚未全部被当前载荷实现：

1. 一帧对应一次完整 FFT 结果，禁止把两个帧无标识地拼接。
2. 使用 `TLAST` 或固定长度明确帧边界。
3. 帧长度按 AXI 总线宽度和缓存行要求对齐。
4. 至少提供帧序号，推荐同时提供硬件时间戳。
5. 中心频率、Span、FFT 点数、数据格式和标度信息可位于帧头，或通过版本化寄存器组提供。
6. 推荐提供协议版本号、载荷长度和有效标志。
7. 若使用定点数，必须明确总位宽、小数位数、符号、饱和方式和字节序。
8. 必须说明 FFT Shift 是否已经完成，以及 DC 对应的频点索引。
9. 不建议在每个频点中重复附带频率；频率应由元数据和索引计算。
10. 可选 CRC 适用于需要检测内存/链路数据损坏的场景，但需评估计算开销。

### 9.3 两种可接受的传输形式

**形式 A：固定长度裸载荷**

- 每帧固定 FFT 点数；
- `TLAST` 标记帧末尾；
- 元数据通过 AXI-Lite 寄存器或软件配置获得；
- 开销低，适合固定配置和极高数据率。

**形式 B：版本化帧头加载荷**

- 帧头包含 Magic、协议版本、帧序号、时间戳、频点数、载荷类型、标度和载荷长度；
- 便于动态切换 FFT 点数和长期扩展；
- 帧头建议固定大小并按总线宽度对齐。

协议最终确定后，应新增独立《PL/PS 频谱数据接口协议》，本文只引用其版本。现有裸 `int32` 形式可作为 bring-up 基线，但不应直接视为最终冻结协议。

### 9.4 缓存一致性要求

- 驱动必须明确 DMA 缓冲是否为 coherent；
- 若非一致性内存，驱动必须在缓冲所有权切换时完成正确的 cache sync；
- 用户态不得自行假定普通 `malloc` 内存可直接用于 DMA；
- 软件不得在 DMA 正在写入时读取同一缓冲；
- DMA 缓冲所有权必须具有明确的“空闲、硬件占用、用户态只读、归还”状态。

### 10.1 总体布局

### 10.2 视觉要求

- 默认深色仪器主题；
- 频谱曲线与网格具有足够对比度；
- 重要告警不得只依赖颜色区分；
- 关键数值在 1920×1080 下清晰可读；
- UI 缩放不得使用写死的绝对坐标；
- 频率、幅度和状态文本不得因数值变长而遮挡主要绘图区；
- 支持窗口模式和全屏模式。

### 10.3 通用绘制优化策略

1. 将画布横向像素列映射到频点区间，对区间求最小值和最大值。
2. 每个像素列保留最小—最大包络，避免窄带峰值在降采样时消失。
3. 当频点数少于像素宽度时直接按频点绘制折线。
4. 降采样坐标数组和帧缓冲应预分配并复用。
5. GUI使用固定刷新定时器，输入帧到来只更新“最新帧句柄”，不为每帧立即触发重绘。
6. 刷新周期内收到多个帧时，只绘制最新完整帧，同时保留接收统计。
7. Marker和测量必须使用完整频点数据，确保绘制优化不影响测量准确性。

### 10.4 CPU Raster 绘制策略

1. `SpectrumPlotWidget` 采用 Raster `QPainter`。
2. 背景、边框、网格和坐标文本缓存到离屏 `QPixmap` 或 `QImage`。
3. 每次新帧只更新曲线、Marker 和必要的动态文本。
4. 对每个像素列计算最小值与最大值；当前实际曲线连接各列最大值形成折线，尚未绘制最小—最大垂线包络。
5. 图像格式优先采用目标平台原生且适合Raster引擎的格式，避免逐帧像素格式转换。
6. 应减少整个窗口的无效重绘，将高频更新区域限制在频谱画布内。

## 11. 性能需求与数据量估算

### 11.1 数据量公式

若每个频点在软件内部使用 4 字节 `float32`：

```text
单帧载荷字节数 = FFT频点数 × 4
持续数据率 = 单帧载荷字节数 × 输入帧率
```

不含帧头、对齐和驱动额外开销的典型数据量如下：

| 频点数 | 单帧（V1，int16+64B 头） | 200 帧/s | 1,000 帧/s |
|---:|---:|---:|---:|
| 1,024 | 2112 B | 0.42 MB/s | 2.11 MB/s |
| 4,096 | 8256 B | 1.65 MB/s | 8.26 MB/s |
| 8,192 | 16448 B | 3.29 MB/s | 16.45 MB/s |
| 16,384 | 32832 B | 6.57 MB/s | 32.83 MB/s |
| 32,768 | 65600 B | 13.12 MB/s | 65.60 MB/s |
| 65,536 | 131136 B | 26.23 MB/s | 131.14 MB/s |

当前 V1 使用 16 位对数幅度；若改为 32 位或 64 位频点，需重新评估 DMA 和 132 KiB 槽容量。

### 11.2 性能指标分类

| 编号 | 类别 | 指标 |

| NFR-PERF-001 | MUST | 支持 1,024～65,536 频点的参数化数据结构和显示。 |
| NFR-PERF-002 | MUST | 1920×1080 下稳定达到不低于 30 FPS 的 GUI 刷新率。 |
| NFR-PERF-003 | TARGET | 在典型目标配置下达到 60 FPS GUI 刷新率。 |
| NFR-PERF-004 | MUST | 输入帧率与显示帧率解耦，输入 1,000 帧/s 时不得产生 1,000 次 GUI 重绘。 |
| NFR-PERF-005 | MUST | PC 模拟环境支持 16,384 点、1,000 帧/s 数据生成和处理，GUI 保持不少于30 FPS。 |

### 11.3 资源指标

以下为初始目标，板端联调后允许形成新的性能基线：

- 典型配置下进程常驻内存目标不超过 256 MiB；
- 固定配置连续运行时内存不得随帧数线性增长；
- 连续24小时测试后，进程内存增长应不超过10 MiB且不存在持续增长趋势；
- 日志和导出文件不得占满系统分区；
- 软件不应长期独占全部 CPU 核心，典型 16,384点/60 FPS场景的CPU占用应在目标板实测后设置正式上限；
- 当CPU负载过高时优先降低显示刷新率或丢弃过期显示帧，不允许阻塞采集导致无界排队。

### 11.4 过载策略

1. 采集层尽可能接收完整帧并维护源侧统计。
2. 管线在采集线程内同步处理，不积压待处理频谱帧。
3. 新完整帧通过 `LatestFrameStore` 覆盖旧最新帧；GUI 只绘制刷新时刻可取得的最新帧。
4. 新离屏渲染上下文覆盖尚未开始的旧上下文，避免渲染任务排队。
5. 源侧接收、提交拒绝、渲染覆盖和 GUI 跳过显示应分别统计，不得静默发生。

## 12. 非功能需求

### 12.1 可靠性

- 软件应支持连续运行24小时以上；
- 模拟数据源异常不得导致主进程崩溃；
- 数据中断后界面保持响应；
- 恢复数据后能够继续显示或经一次明确重启操作恢复；
- 参数快速连续修改不得产生悬空指针或线程竞争；
- 所有跨线程对象应具有明确的创建、使用和销毁线程归属。

### 12.2 可维护性

- 模块职责清晰，不把数据生成、DMA、轨迹计算和绘制写入同一个窗口类；
- 公共接口使用版本化数据结构；
- 核心类和复杂算法具有必要注释；
- 配置项和常量集中管理；
- 错误码与日志信息可追踪到具体模块；
- 格式转换器、降采样器和测量引擎可脱离 GUI 单元测试。

### 12.3 可扩展性

- 后续新增多通道瀑布或时间选通功能时复用统一频谱帧发布机制；
- 支持未来一个数据源发布多个逻辑通道；
- 绘制后端可扩展为 CPU Raster 和可选 GPU 两种实现；
- 协议解析器与 DMA 设备访问分离，协议变化不要求修改驱动封装；
- 测量功能通过独立接口注册，不直接耦合主窗口。

### 12.4 可移植性

- 禁止在业务层直接包含 Windows 或 Linux 专用头文件；
- 平台相关实现放入独立目录并通过接口隔离；
- 文件路径使用 Qt 跨平台接口；
- 不假设目标端存在桌面环境；
- 应支持至少一种无GPU的目标QPA后端，优先验证`linuxfb`，若硬件显示栈提供X11则同时验证`xcb`。

### 12.5 安全性

- 配置文件和场景文件必须校验类型、范围和数组大小；
- 不信任 DMA 帧头中的长度字段，解析前必须与实际缓冲长度比较；
- 文件导出不得无提示覆盖已有文件；
- 日志不得记录敏感凭据；
- 数据长度计算必须防止整数溢出和越界访问。

## 19. 风险与应对

| 风险 | 影响 | 应对措施 |
|---|---|---|
| Windows Qt6与目标Qt5存在API差异 | 后期移植返工 | 双版本CMake、兼容层、尽早安装Qt 5.15.x持续构建 |
| 目标板无可用GPU | 高频绘图CPU占用高 | Raster自绘、静态缓存、像素包络降采样、固定刷新率和按需NEON优化 |
| PL协议晚确定 | DMA接入延期 | 统一内部帧和数据源接口，协议解析独立 |
| DMA峰值数据率过高 | 丢帧或延迟累积 | 预分配缓冲、零/少拷贝、最新帧策略、明确过载模式 |
| 幅度标度不明确 | 显示数值不可信 | 一期使用dBFS并标记未校准，后续加载标定公式 |
| Qt未加入rootfs | 目标程序无法运行 | 选择Qt packagegroup并生成Qt5 SDK，部署前检查动态依赖 |
| 显示后端未知 | 板端界面启动失败 | 尽早验证linuxfb/xcb及字体、输入设备和屏幕驱动 |
| 软件渲染撕裂或刷新不足 | 显示体验下降 | 控制刷新率、减少无效重绘、验证QPA后端双缓冲能力 |
